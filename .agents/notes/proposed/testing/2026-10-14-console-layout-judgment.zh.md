# Proposal: 控制台页面的排版改动由渲染与测量判定，而不是源码字符串

[English](2026-10-14-console-layout-judgment.md) | 中文

Status: proposed
Date: 2026-10-14
Class: testing

## 问题

改这个插件页面外观的人，必须先停掉正在运行的服务、重新构建并安装，才能看到结果；改完还得在真实页面上逐个量元素，才知道有没有东西移位。于是没人敢把两个页面的外观统一成一套。

2026-10-14 这一次排版工作留下了具体数字（`5418504`、`7cef34c`、`edbbe9f`、`cb083f3`、`f413ecf`、`0432907`）：

- 每一版都花掉一轮 `./build.sh` + `./install.sh`，而 `install.sh` 覆盖插件前会先停掉 Jellyfin：每次约十秒不可用，那一轮里跑了八次。
- 「没坏」的含义是 [test_backend_retired_config_page.py](../../../../tests/backend_retired/test_backend_retired_config_page.py) 里的源码字符串断言 —— `assertIn("flex: 0 0 var(--jdl-actions-width)")`、`assertIn("运行中")`、`assertNotIn("status.pid")` 等，这个文件现在共 53 条。页面错着的时候它们照样全绿：等长这条要求被 `cb083f3` 记成同时覆盖媒体目录输入框（实测 803.5 px）与站点输入框（627.5 px），只有复核的人量了坐标才发现。
- 几何靠人在浏览器工具里逐个量，每版六到十个元素：`#jdl-media` x=254.875 w=627.515625、两行的 `[data-action="up"]` x=890.390625、`#jdl-port-label` 高 30.125。
- 可计算的属性同样是手算的：六组 WCAG 对比度，其中两组不达标（`#2e9e4f` 3.43:1、`#d79b00` 2.45:1，对白底）。
- 软刷新页面会拿到缓存里的旧页面：有一轮测量就是量在它上面、随后作废；硬刷新这件事之所以被发现，只是因为有个坐标死活不变。

代价不在重建。代价是任何关于页面的说法都要靠人看一眼才能算数 —— 于是排版改动没法被复核，改版也没法切成别人能接手的块。

## 提案

给两个控制台页面一处统一的判定面，并让它成为判断排版改动对不对的那个东西。

1. 渲染步骤用无头 Chromium 加载 `Configuration/configPage.html`，并带上控制台自带的那份主题样式（主题发布的 `main.jellyfin.*.css`）；不运行 Jellyfin，也不安装插件。
2. 测量步骤读取每个已声明元素的盒子与计算样式，然后断言页面必须保持的关系：同一列表内输入框等长、行尾三个按钮跨行同列、服务端口那行的部件在同一行、小节标签与其它小节标题同字号、状态徽标配色过 WCAG AA。
3. 期望值放在判定面旁边的**一个**文件里，每次运行都把量到的值打出来 —— 于是更新期望值是一次有意的编辑，而不是对着一条红去猜。
4. 这条命令在 Jellyfin 运行期间也能跑，且不碰已安装插件目录下的任何文件；于是判断一次排版改动不再需要 `./install.sh`，软刷新的坑也一起消失，因为判定面读的是文件而不是被服务出来的页面。
5. 判定面渲染哪些文件，由 `source` 改动面的声明推导出来；于是第六个脚本分片或新增的样式表不可能不声不响地留在覆盖之外。

判定面必须守住的约束：只用 Python 标准库，不新增包依赖、不引入 Node 工具链（本仓库的测试命令是 `python3 -m unittest discover -s tests`）；本机没有 Chromium 时，判定面要以点名的原因失败，而不是报成功。

新增：`tests/` 下的一个测试模块与其期望值文件（`tests` 改动面）、旁边的渲染助手，以及在 [workflow.json](../../../../tools/workflow.json) 里声明的一条 `checks[]` 条目，好让 `check-invariants` 能按名字报出这条判定面。

第一版交付会回答的待定问题：从标准库 Python 驱动本机已装的 Chromium（走它的 devtools 协议）是否小到值得保留，还是渲染步骤需要一个显式声明的开发依赖。判定面无论哪种都值得建；依赖这个决定等拿到 diff 再下。

## 曾考虑的替代方案

**保留源码字符串断言与人肉量坐标。** 它们便宜、跑在既有命令里，也确实钉住文本类回归（比如 `status.pid` 又冒出来）。它们落选是因为它们断言的是源码的形状而不是结果：等长那条说法是错的时候，其中五条照样全绿；而最近六版动过的每一条几何关系，它们都看不见。

**在运行中的实例上、真实控制台里测。** 保真度最高，不需要替身样式表，浏览器本来就在手边。它落选是因为那样一来证据就依赖一个活着的服务和一个管理员会话：要产出它就得停服重装 —— 正是本提案要消掉的代价 —— 而且它没有任何一部分能跑进仓库自己的验收命令里。

**比对截图，而不是断言几何。** 视觉差分能抓到几何抓不到的东西（间距手感、换行、重叠），本次会话里也确实截了图并逐张看过。它作为第一片落选，是因为每一处差异都是一次人的判断，判定面就无法自己说「这里坏了」；等关系立住之后，它是自然的第三阶段。

## 验收标准

- [A1] `source` — 判定面覆盖每一个前端文件：`Configuration/configPage.html`、`Web/inject_01_core.js` 到 `Web/inject_05_render.js`、`Web/style.css`。这份清单由改动面声明推导，所以覆盖新分片不是可选项，漏掉一个会失败而不是悄悄通过。
- [A2] `tests` — 把按钮区改回 `flex: 0 0 auto`（`cb083f3` 修掉的那个缺陷）会让某条标准失败；第一次见到红的那次运行记在这里，因为没人见它红过的守卫只是猜测。
- [A3] `tests` — 判定面在 Jellyfin 运行期间通过，既不需要 `./build.sh` 也不需要 `./install.sh`，连跑两次后 `git status` 是干净的。
- [A4] `source` — 判定面渲染的是源码文件，所以改一处样式再跑就能看到新的量值、不必重建；没有渲染器可用时，它以点名的原因失败，而不是成功。
- [A5] `docs` — 这条命令写在 agent 找本仓库验收命令的地方，并且「页面改动只能靠停服确认」这个说法从 [README.md](../../../../README.md) 里消失。

## 风险

- 替身渲染不是控制台本身。主题样式取自已安装的控制台，但外围 DOM 与它自己的重置规则不同，所以某条关系可能在判定面里成立、在真实页面上坏掉。第一次运行会与 2026-10-14 量到的真机基线对账 —— 输入框 x=254.875 w=627.515625、两行的上移按钮 x=890.390625、`#jdl-port-label` 高 30.125 —— 并且这次对账保持可重跑。
- 只要页面自己也留一份，期望值就成了排版事实的第二个家。现在接受这一点，因为每次运行都会打印量到的值、更新是一次显式编辑。这就是被推迟的「排版事实一个家」那一片：当同一个事实在两个家之间第二次漂移时（就像 2026-10-14，[README.md](../../../../README.md) 描述了一个页面已经没有的 Python 安装控件），那一片就成为下一个提案。
- 渲染器是最脆的一环。用标准库 Python 走 devtools 协议比调一次库函数要多写代码，而在没有 Chromium 的地方这条判定面是空的而不是通过的。如果它被证明易碎，退路是显式声明一个开发依赖 —— 这个决定本提案有意先不做。
- 改版本体不在本提案里。等判定面能稳定变红，另有一个提案负责统一两个页面的外观；更早决定它，就等于写出没有任何东西能检查的验收标准 —— 这也正是本记录要先存在的原因。
- 外观在像素层面仍然未被验证。本提案钉住的是关系与可计算的属性，不是观感；判断观感仍是人的步骤，判定面产出的截图只是让这一步更便宜。

## 交付阶段

1. 配置页：渲染 + 几何与对比度断言、由改动面推导的文件覆盖、以及 A2 的红色见证。
2. 注入面板：同一条判定面跑 `Web/inject_0*.js`，带一个替身宿主 DOM，复用同一个期望值文件 —— 面板只存在于 Jellyfin 的条目页里，所以这一阶段才让第一阶段的关系在那里也成立。
3. 截图作为证据：判定面输出复核者本来就会看的截图，让复核读一份点名的产物，而不是再驱动一次浏览器。
