Jellyfin Downloader 下载资源链路

模块粒度 · 每一步只写「谁执行了什么动作」 · 不出示函数名与参数默认值

从 Jellyfin 详情页点「获取资源」，到文件按规范命名落进媒体库并触发库刷新，一共经过 3 层、12 个阶段。每张阶段卡片的最后一行给出这条动作的出处源码，需要细节时按它去读。

事实基准 commit 2d7da69 后端 Python 3.9+ / 标准库 插件 .NET 9 / Jellyfin 10.11 后端只监听 127.0.0.1
入口 / 请求 代理与进程管理 取源（两条通道） 打分与排名 提交与下载 校验与归档 云盘取回 失败 / 终止

一、三层拓扑

三条通信约束解释了大部分设计：浏览器不直连后端、后端随 Jellyfin 生命周期起停、数据根由插件注入。

二、主链路（12 个阶段）

实线是主路径；失败与分支统一收在下面的「失败分支」里。

0入口
Web/inject_02_entry.js
  1. 详情页挂「获取资源」按钮；非详情页挂右上角 header 图标（同一个面板）。
  2. 从页面上下文 预填 片名 / 年份 / 季集，打开面板。
  3. 剧集页先 取季列表（服务端查媒体库），选季再搜。
产物：带上下文的面板；季级命名空间（<剧名>.sNN.*.json）
1组装搜索请求
Web/inject_04_search.js
  1. 组装片名 / 类型 / 年份 / 季集 / 别名 / 通道选择（磁力 / 云盘 / 两者）。
  2. 带入 严格按季、单源（只跑 L1 关键字）两个开关。
  3. 最低分阈值取插件配置，面板内可临时调。
产物：POST /api/search 的请求体
2同源代理
Controllers/JellyfinDownloaderController.cs
  1. 仅管理员（RequiresElevation）放行。
  2. 路径必须命中 白名单前缀：search / snapshot / submit / watch / pan/。
  3. 转发 到后端实际监听地址（端口自增后不能读配置里那个字段），失败回 502 与原因。
产物：浏览器与后端之间的唯一通道（因此没有 CORS，也不用给后端做鉴权）
3建搜索任务
console_server/http_api.py → console_server/jobs.py
  1. 校验片名与类型，推导落点（必须在暂存区或媒体根内）。
  2. 生成本轮唯一候选文件路径，丢进后台线程，立刻返回 job_id。
  3. 进度与结果由 状态端点 + 快照 供面板读取。
产物：job_id；任务注册表（最多留 50 个，日志行超限滚动）
4查重
download/check_exists.py
  1. 在分类目录里 模糊匹配片名（忽略大小写、空格、标点、年份）。
  2. 命中目录且含真实视频（> 100 MB）→ ALREADY_EXISTS；空壳目录 → 继续下载。
  3. 结论写进快照的 exists 字段，面板直接可见。
产物：exists 结论
5磁力通道 · 资源站取源
search/search_pool.py + search_pool_*.py + torrents_csv_source.py
  1. 关键词阶梯：L1 发布者关键字排最前，其后别名/原始片名带年份、裸片名、逐词追加。
  2. 多资源站 等分每个关键词的墙钟预算（加站是分摊，不是延长单轮）。
  3. 第二通道 torrents-csv 补齐 做种数快照（带快照年龄，供打分侧判断可信度）。
  4. 去重后写候选文件与池快照。
产物：候选磁力文件 · 池快照 ｜ 失败：站点配置坏掉时明确报 SOURCE_CONFIG_ERROR
6云盘通道 · 分享提取
pan/pan_search.py + pan/pan_pool.py
  1. 把配置里带 {q} 占位符的站点当 搜索页，抓分享链接与提取码。
  2. 没有这种站点时明说没有入口，不给一个语焉不详的空结果。
  3. 云盘候选与磁力候选 进同一套打分：转存前按标题粗排，转存后读本机云盘缓存换真实文件清单精排。
产物：云盘候选文件（含提取码）
7候选池 · probe 打分
probe/probe_magnets.py 编排 probe_health · probe_metadata · probe_round + candidate_score/
  1. 合并去重：磁力与云盘是两条独立通道，一侧读不到不该把另一侧一起丢掉。
  2. 健康度：tracker announce / scrape 取做种数与可用性。
  3. metadata：并发抓种子元数据，命中池缓存则跳过。
  4. 加权打分 → 全量排名 → 交付前若干名。四维不淘汰，只有结构合法性与磁盘安全是硬否决。
产物：ranked 结果 JSON ｜ 失败：软预算耗尽时打印 PROBE_PARTIAL 且不写快照——保留上一份历史，不拿旧候选冒充本轮
8快照写入 · 面板轮询
console_server/probe_state.py + build_console.py
  1. 写 probe 结果、云盘候选（保留提取码）、本轮状态（context）。
  2. 组装成面板视图：候选 + 迅雷任务 + 本轮状态。
  3. 面板 每 5 秒轮询；空轮时磁盘上那份候选会被标 previous_round，不冒充新结果。
产物：state/snapshots/*.json · 面板候选列表与四维拆解
9选择与提交
Web/inject_05_render.js → POST /api/submit 或 /api/watch
  1. 展示总分与 四维拆解、体积、码率、字幕、片源；可设最低分阈值。
  2. 磁力候选两个按钮：后台监控（直接建 watcher）与 提交迅雷（走守门流程）。
  3. 云盘候选只有一个「打开云盘」（转存是浏览器侧动作）。
  4. 端点校验 info hash 与分类，再交给后端脚本。
产物：提交请求 ｜ 提交端点带 --no-watch，由工作流决定何时起 watcher
9′提交与守门
download/submit_xunlei.py
  1. 先按 体积策略 拒不合规资源（低于/超出配置区间直接拒绝）。
  2. 设置迅雷默认保存路径为 同盘暂存目录 → 打开磁力 → 等任务落库。
  3. 校正保存路径与选片；把已抓到的 metainfo 写进任务目录（迅雷有时自己不写，之后「继续下载」会报取种子失败）。
  4. 在线校验补丁是否真的持久，没生效就撤回。
  5. 实测吞吐换算 ETA，超上限则暂停任务并只清本次任务文件。
产物：已入队的迅雷任务 ｜ 失败：体积或 ETA 不合格 → 暂停 + 只清本次文件
10下载监控
download/watch_download.py + media_download_lib/watcher.py
  1. 起独立进程并写状态文件；同一 info hash 已有存活 watcher 时直接复用，不重复监控。
  2. 每 15 分钟（默认）只读查询迅雷数据库 取进度与速度，换算 ETA 写状态。
  3. 面板通过快照读到的就是这份状态。
产物：state/watches/<IH>.json|log ｜ 失败：任务消失 / 迅雷报错 / ETA 长期超上限，各有独立终态
11校验 · 归档 · 清理 · 刷新
media_download_lib/finalize.py → download/verify_media.py → download/handle_media_issues.py
  1. 归档：定位本次发布目录，逐个视频校验，按 剧名 S01E01.ext / 片名 (年份).ext 规范命名，同盘原子移动进媒体库，顺带搬外挂字幕、清垃圾、收空目录。
  2. 六层校验：流信息（分辨率/码率区间）→ 三段抽样解码 → 集号一致性（缺集/重复/残片）→ Jellyfin 数据库对账 → 结构卫生 → 硬字幕启发式。
  3. 处置：重复集按哈希去重、删可疑小文件、处理孤儿目录与残留；库与文件不一致时 触发库刷新（拿不到令牌则退回「请手动刷新」）。
  4. 需要人工的事（缺集、缺字幕、码率不合规、疑似硬字幕）列成清单，不静默吞掉。
产物：媒体库里的规范文件 + 库刷新 ｜ 失败：校验不过 → invalid，文件留在原地供排查

失败分支

  • 取源失败：站点配置不可用 → SOURCE_CONFIG_ERROR；没有磁力入口 → 明说本轮没写出候选，不拿上一轮文件喂 probe。
  • 打分早退：软预算耗尽 / 阶段超时 → PROBE_PARTIAL，结果不完整但落盘，面板能看到。
  • 提交被拒：体积不合策略、ETA 超上限、在线补丁没生效 → 暂停任务并只清本次任务的文件。
  • 下载异常：任务消失、迅雷报错态 → 写 missing / error，文件留在原地。
  • 校验不过：finalize 或六层任一不过 → invalid，不归档、不删文件。

三、云盘通道（浏览器与脚本交替执行）

云盘没有可以端到端自动化的接口，所以 plan 会把下面这张步骤表算出来交给用户照做；脚本负责每一步的校验与最后的取回监控。

P1浏览器 · 打开分享页
pan/pan_transfer.py · plan 步骤 1
  1. 带提取码打开分享链接，未登录先扫码。
  2. 这是人工步骤，脚本只能把 URL 和提取码准备好。
P2浏览器 · 保存到云盘
pan_transfer.py · plan 步骤 2
  1. 点「保存到我的云盘」，目录选配置的云盘目录。
P3脚本 · 确认真实文件清单
pan_transfer.py verify-transfer + pan_pool.py + candidate_score/
  1. 读本机云盘缓存，确认文件真的落到云盘。
  2. 此时才第一次拿到可信的分数输入（真实文件名/大小/扩展名），据此精排。
产物：云盘候选的真实排名
P4浏览器 · 进云盘页
pan_transfer.py · plan 步骤 4
  1. 打开云盘页，进入已转存目录。
P5脚本 · 指定保存路径
pan_transfer.py set-save-path
  1. 把迅雷默认保存路径指到暂存区（与磁力通道同一个暂存根）。
P6浏览器 · 下载到本地
pan_transfer.py · plan 步骤 6
  1. 勾选要取的集/文件，点「下载到本地」。
P7脚本 · 确认取回已开始
pan_transfer.py verify-retrieve
  1. 列出 cloud/getback 任务，确认取回已开始。
  2. 一条取回任务都没有时明确报 NO_RETRIEVE_TASK，而不是空等。
P8脚本 · 等待并归档
pan_transfer.py watch --detach
  1. 等取回完成，然后汇入同一条校验 + 归档路径（就是上面的阶段 10–11）。
产物：与磁力通道一致的终态与状态文件

四、状态与失败口径

搜索状态（写进快照，面板直接显示）

状态含义
ok本轮跑完且有交付候选
best_below_min_score有排名结果，但第 1 名低于最低分阈值，不交付
best_dead_swarm第 1 名 metadata 不可达（死种），交付了也会种子解析失败——明确降级，不硬交
swarm_dead都拿不到 metadata 且 live announce 无外部做种者：是种子死了，不是网络问题
metadata_failed拿不到 metadata 但外部 peers 存在：网络/tracker 问题，不是资源不存在
no_eligible_resource候选都被结构性否决（结构合法性与磁盘安全是硬门槛，四维打分不淘汰）
probe_partial软预算耗尽 / 阶段超时，结果不完整
rc_N脚本以非零码退出（如资源站配置坏掉时取源退 2），结论另在 job 日志里

另有两个容易混的名词：probe_round_empty 是本轮没写出新结果时快照上的字段（那份候选属于上一轮），不是状态； SOURCE_CONFIG_ERROR 是 stdout 上的 token，面板在 job 日志里能看到，状态本身会落到 rc_2。

watcher 状态（面板的任务卡片读它）

状态触发文件处置
running每轮采样—
completed / completed_with_warnings归档与六层校验都过已归档进媒体库，触发库刷新
invalid完成但校验不过留在原地供排查
error迅雷报错态留在原地
missing连续查不到任务—
eta_abortedETA 长期超上限暂停任务，清本次任务文件

其它关键口径

  • 落点守卫：暂存区或媒体根内，所有端点在动文件前都查一遍。
  • 同盘原子移动：暂存区固定为媒体根下的 .staging，这也是「迅雷只允许写暂存区」的原因。
  • 一轮搜索的墙钟上界：总超时 900s，其中 L1 取源 600s、probe 软预算 720s——软预算刻意小于整轮超时，让 probe 在被杀之前自己收工并把 partial 结果落盘。
  • 迅雷数据库全程只读；写动作（暂停任务、清理）走明确的任务级操作，且只碰本次任务。

六、未核实项

  • 面板上「最低分阈值」是否回写插件配置：只确认面板内可临时调整，未核实是否持久化。
  • 一轮 probe 的真实墙钟耗时：源码注释明确写着「是推算，不是本机实测」，真实网络下的预算行为尚未跑过。本页照录该口径，未自行补测。
