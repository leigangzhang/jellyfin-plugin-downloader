# 双语与语言规则（i18n.md）

[English](i18n.md) | 中文

本套件有一位中文母语的 owner，也有用英文工作的 agent，所以**两边都要据以行动的事实**必须住在两份文件里，而且两份必须说同一件事。[documentation.md](documentation.zh.md) owns 文档 kind、放置与预算；本文件 owns 语言。

## 范围与排除

套件里每个 `*.md` 文件都是一对，四类除外：

| 排除项 | 为什么保持单语 |
|---|---|
| `AGENTS.md` | agent 常驻上下文的常驻规则；指令文件保持英文，托管本套件的仓库也是这么做的。 |
| `.agents/skills/*/SKILL.md` | 由各自的 `description` 加载；一份文件同时服务两类读者，翻译副本永远不会被加载。 |
| `docs/check-catalog.md`、`dev/evidence/*` | 生成产物，不是文档：整页投影跟随它事实源的语言，跑动记录是工具写下的输出。[documentation.md](documentation.zh.md#生成镜像还是链接) 禁止手改其中任何一个。 |

新加的 `*.md` 文件一落地就进入范围。没有分批名单，也没有本表之外的逐文件豁免。

## 成对与一致性记录

一对是同一目录下的三个同名文件：`X.md`（英文）、`X.zh.md`（中文）、`X.i18n.yaml`（一致性记录）。一致性记录按**承载语言相关内容的小节**各记一条；键是该小节标题的英文路径（第一个标题之前的正文记为 `/`，路径重复时依次加 `~2`、`~3`……），`en` 与 `zh` 是该侧顶层块（top-level block）的 16 位十六进制 SHA-256 摘要，围栏代码块不计入：

```yaml
/docs-md/budgets:
  en: 1a2b3c4d5e6f7a8b
  zh: 8b7a6f5e4d3c2b1a
```

`python3 tools/pair-docs.py --write` 重算这些记录，`--check` 则会对**任何一个**记录摘要与当前内容对不上的小节报错。写入这条记录，就是"这一对在这些确切内容上确认同步"这个动作本身，它可被 review。

## 保持英文的标识

读者拿到自己语言的正文，机器拿到两侧相同的标识。以下内容两侧逐字相同：

- 列表记号、列表类型、有序列表起始编号与条目数；表格的行数与列数；
- 围栏代码块，包括 info 字符串和块内每一条注释；
- 行内代码：路径、命令、开关、配置键、check id、surface 名，以及 `[A1]` 这类验收编号；
- 专名与产品名（`GitHub`、`TypeScript`、`DeepSeek`）；
- 记录标题的类型前缀（`# Decision: `、`# Postmortem: `）—— 它点名的是记录的种类，不是它的主题；
- 术语表与大白话表里的术语标题，好让同一个锚点从任一语言都可用 —— 把术语标题译成中文会让 `term-headings-ascii` 变红。

标题与表头属于正文，所以中文侧翻译它们。要求"某个小节必须存在"的检查同时接受两种写法：`tools/workflow.json` 里每一条 `sections` 会把它们并列声明。

## 正文会被翻译

上面那张单子之外的一切都翻译，而且对侧必须说出正本所说的：不新增警告、前置条件、例子或版本声明，也不丢掉任何一条。译的是意思；目标语言的语法想要另一种句式就重写句子 —— 简洁的保持简洁，但不许为了通顺丢掉任何一个从句。两侧都只写当前态；历史住在 commit 与决策记录里。

## 排版

中文侧在中文与拉丁词、中文与数字之间放一个半角空格（`每个 check 注册 3 条规则`），用全角标点（`，。：；？！（）「」`），并列项之间用顿号，称读者为"你"，绝不使用全角数字或全角拉丁字母。行内代码里、原样引用的完整英文句子里，以及数字里（`3.5`、`1,024`）保持半角标点。英文侧遵循托管本套件的仓库的正文规则。两侧都**一段一行**，并且文件末尾恰好一个换行。

## 链接与语言切换器

H1 之后的第一个段落就是语言切换器：英文侧写 `English | [中文](X.zh.md)`，中文侧写 `[English](X.md) | 中文`。指向**成对文档**的相对链接用本侧的语言文件，而它的 fragment 点名**链接所指向那一侧**的标题 —— 所以中文侧链接写的是中文标题的锚点。指向未成对目标的链接保持作者写下的路径与英文 fragment。`python3 tools/pair-docs.py --check` 会把每条 fragment 解析到它的目标上，点名不到任何标题就红。

## 更新一对

在**同一次改动**里改两侧，然后用 `python3 tools/pair-docs.py --write X.md` 重录。只针对改动的那一节修补对侧，不要整篇重译。只改一侧的改动会在下一次 `--check` 变红；带不平的一对，不许合并。

## 闸门证明了什么

`python3 tools/pair-docs.py --check` 证明这些：三个同名文件都在、两侧的切换器都在、围栏代码块逐字节相同、每条相对链接都指向存在的文件、每条 fragment 都能在目标里点到一个标题、两侧的形状一致 —— 标题层级、围栏 info string、表格的行 × 列、列表的种类与条数 —— 以及记录的摘要仍等于重算出来的摘要。它判不了两侧是不是真的说了同一件事、术语选得好不好、中文读起来顺不顺 —— 那一半归 review。托管本套件的仓库可能对它看得见的那几个文件跑自己的配对闸门；对那些文件，那个闸门才是权威，在这里它管着 `pairing.hostCanonical` 点名的五个文件 —— 四份 README 加生命周期地图 —— 它们的记录必须与该闸门的渲染器逐字节一致。

## 已知限制

- 不做生成区间（generated region）的建模；套件里没有这种结构，哪个文档要加，就必须在同一次改动里扩展 `pair-docs.py`。
- 链接归一化只覆盖**本套件自己的成对文档**内部的目标；指向别处某对文档的链接按作者写下的样子参与摘要。在被宿主管辖的配对内部，指向**受管辖 README** 的链接仍然跟随语区，因为那个目标本身就在宿主语料里；而指向其它任何文档的链接两侧都保留英文路径，所以中文读者从受管辖页面点过去会落到英文原文，再用那一页顶部的切换器回来。另外 `pair-docs.py --check` 会解析每一条相对链接：层级错了一层的路径会直接变红，而不是被当成文本来比对。
- 闸门查的是结构与记录摘要，不是语义。译文质量、术语选择与行文是否自然，仍然是 review 的责任。
