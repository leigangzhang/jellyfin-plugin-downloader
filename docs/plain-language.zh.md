# 大白话

[English](plain-language.md) | 中文

词汇问题的另一半：[glossary.md](glossary.zh.md) 规定一个词在**本套件内部**是什么意思，而本页规定怎么把它讲给不共享这套词汇的人。读一条回复、一段 PR 描述、一条发布说明、一份事故摘要或一条提交信息的人没有读过术语表 —— 没交到他手上的词，他用不上。

## 如何使用本表

- 写给人看的文字之前先在这里找；找不到就用日常句子代替那个术语，事后再把术语补进本表。
- 每条给出大白话句子与一个替换示例。示例才是重点：它展示这个替换在真实句子里长什么样。

## 什么时候必须展开

1. **面向人的文本里首次出现时。** 展开一次，或者干脆换掉 —— 回复、PR 描述、发布说明、事故摘要、提交信息。
2. **绝不假设某个词已经被交到读者手上。** 术语表是 agent 的词汇，不是读者的；读者只有已经出现在这条消息里的词。
3. **一次只引入一个新词。** 一段里塞两个自造词，读者会直接跳过这一段。
4. **点名行为者与事实**，而不是机制背后的隐喻：写清什么变了、什么在跑、读者要做什么。
5. **文档不适用这条。** 记录、契约与常驻文档的存在就是为了建立词汇，所以它们用术语，并链向术语表。

## 术语与它们的大白话含义

### seam

一个可以换成别的实现、而不用动其余部分的部件。

*不要写*"shell seam 把它拒了" → *写*"bash-local 与 bash-sandbox 是同一个 shell 能力的两种实现，这一种拒绝了这条命令"。

### surface

一次改动碰到的那组文件，加上其中任何一个变了就必须跑的那些检查。

*不要写*"这个不在 surface 上" → *写*"这个文件没有声明任何检查，所以不会有东西自动为它跑起来"。

### evidence

真正跑过的那些命令，以及它们打印了什么 —— 落成一个文件，每条命令一个判定。

*不要写*"那不算证据" → *写*"那条命令还没跑过，所以这里没有任何东西显示它会打印什么"。

### gate

一步要算完成之前必须通过的那些检查。

*不要写*"闸门红了" → *写*"`pair-docs --check` 失败了：这一对文件的两侧已经不再一致"。

### projection

由某一个源生成出来的东西；改它等于改错了文件。

*不要写*"更新一下投影" → *写*"改 `tools/workflow.json`，然后重跑 `gen-docs.py`"。

### mirror

一份会与原文逐字比对的块副本，所以它漂移了必然被发现。

*不要写*"手工保持同步" → *写*"这个块在 `dev/contracts/mirrors.json` 里登记过，一旦与源不一致检查就会失败"。

### empty corpus

检查没找到任何文件可看，于是它什么也证明不了，被判无效。

*不要写*"这条检查是绿的" → *写*"这条检查匹配不到任何文件，而一条无法失败的检查会被判无效"。

### station

这套件围绕的工作流上的一步，从意图到退役。

*不要写*"我们到第 11 阶段了" → *写*"这是退役那一步：删掉这份记录，或者把它封存"。

### criterion

"做完了"清单上的一条，背后有一条会为它变红的检查。

*不要写*"验收标准已满足" → *写*"每一条都点名了检查，而那些检查全都通过了"。

### seal / frozen

永久锁上：文件的字节与日期都被记下，此后永不编辑。

*不要写*"先归档，以后再改" → *写*"封存就是冻结；要改内容，就解封并写一份新记录"。

### pair / counterpart

同一个页面的两种语言：英文原文与它的中文对侧。

*不要写*"两侧都更新一下" → *写*"改英文页、改它的中文对侧，然后重录这一对"。

### canonical

其它译文由它翻译过来的那一侧。它说明哪份文件是权威，不说明哪份文件是对的。

*不要写*"canonical 的真相" → *写*"英文是这份文件被翻译过来的那一侧"。

### budget

一个文件的大小上限，按词或按行。

*不要写*"它违反预算了" → *写*"这一页是 1353 词，而它的上限是 1400"。
