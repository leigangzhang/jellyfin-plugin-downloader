# i18n.md

English | [中文](i18n.zh.md)

This kit is read by a Chinese-speaking owner and by agents that work in English, so a fact both sides must act on lives in two files that must say the same thing. [documentation.md](documentation.md) owns document kinds, placement, and budgets; this file owns language.

## Scope and exclusions

Every `*.md` file in this kit is a pair, except four classes:

| Excluded | Why it stays single-language |
|---|---|
| `AGENTS.md` | Standing orders an agent keeps in context; instruction files stay English, as they do in the repository that hosts this kit. |
| `.agents/skills/*/SKILL.md` | Loaded by their `description`; one file serves both readers, and a translated copy would never be loaded. |
| `docs/check-catalog.md`, `dev/evidence/*` | Generated output, not a document: a whole-page projection follows the language of its fact source, and a run record is output written by a tool. [documentation.md](documentation.md#generated-mirrored-or-linked) forbids patching either by hand. |

A new `*.md` file enters scope the moment it is added. There is no rollout list and no per-file exemption beyond this table.

## Pairs and the consistency record

A pair is three sibling files in one directory: `X.md` (English), `X.zh.md` (Chinese), and `X.i18n.yaml` (the consistency record). The record holds one entry per heading section that carries language-specific content; the key is the section's English heading path (`/` for text before the first heading, `~2`, `~3`, … when a path repeats), and `en` and `zh` are 16-hex SHA-256 digests of that side's top-level blocks, with fenced code blocks left out:

```yaml
/docs-md/budgets:
  en: 1a2b3c4d5e6f7a8b
  zh: 8b7a6f5e4d3c2b1a
```

`python3 tools/pair-docs.py --write` recomputes the records, and `--check` fails on any section whose recorded hash no longer matches its content. That record is the reviewable act of confirming the pair is in step at these exact contents.

## Identifiers stay English

A reader gets prose in their own language; a machine gets the same identifiers on both sides:

- list markers, list kinds, ordered-list starts, and item counts; table row and column counts;
- fenced code blocks, including the info string and every comment inside;
- inline code spans: paths, commands, flags, config keys, check ids, surface names, and criterion ids such as `[A1]`;
- proper nouns and product names (`GitHub`, `TypeScript`, `DeepSeek`);
- a record title's type prefix (`# Decision: `, `# Postmortem: `), which names the record kind;
- a term heading in [glossary.md](glossary.md) or [plain-language.md](plain-language.md), so one anchor works from either language — `term-headings-ascii` fails a translated one.

Headings and table headers are prose, so the Chinese side translates them; a check that requires a section lists both spellings in its `sections` entry.

## Prose is translated

Everything outside that list is translated, and the counterpart says what the authored side says: no warning, prerequisite, example, or version claim is added, and none is dropped. Translate the meaning and rebuild the sentence where the target grammar wants it — terse stays terse, and no clause is lost to fluency. Both sides state current state; history belongs in commits and decision records.

## Typography

The Chinese side puts one half-width space between Chinese text and Latin words or numerals (`每个 check 注册 3 条规则`), uses full-width punctuation (`，。：；？！（）「」`), separates parallel items with 顿号, addresses the reader as 你, and never uses full-width digits or Latin letters. Punctuation stays half-width inside code spans, inside a complete English sentence quoted as-is, and inside numbers (`3.5`, `1,024`). The English side follows the prose rules of the repository that hosts this kit. Both sides keep one physical line per paragraph and end with exactly one trailing newline.

## Links and the language switcher

The paragraph immediately after the H1 is the language switcher: `English | [中文](X.zh.md)` on the English side, `[English](X.md) | 中文` on the Chinese side. A relative link to a paired document uses the side's own locale, and its fragment names a heading on the side it points at, so the Chinese side links to the Chinese anchor; a link to an unpaired target keeps the authored path and its English fragment. `python3 tools/pair-docs.py --check` resolves every fragment against its target and fails on one that names no heading.

## Updating a pair

Edit both sides in the same change, then re-record with `python3 tools/pair-docs.py --write X.md`. Patch the counterpart against the edited section rather than re-translating the file. A one-sided edit is red at the next `--check`, and a pair that cannot be brought level is not mergeable.

## What the gate proves

`python3 tools/pair-docs.py --check` proves that all three siblings exist, that both switchers are present, that fenced code blocks match byte for byte, that every relative link names a file that exists, that every fragment names a heading in its target, that the two sides are the same shape (headings, fence info strings, tables, lists) and that the recorded hashes equal the recomputed ones. It cannot judge whether the two sides say the same thing, whether a term was chosen well, or whether the Chinese reads naturally — that half belongs to review. A repository that hosts this kit may run its own pairing gate over the files it can see; that gate is the authority for those files, and here it governs the five files in `pairing.hostCanonical`, whose records must stay byte-identical to that gate's renderer.

## Known limits

- Generated regions are not modelled; a document that adds one must extend `pair-docs.py` in the same change.
- Link normalization covers this kit's host-governed pairs only; a link elsewhere is hashed as authored. A link to a governed README still follows the locale even there, because that target is inside the host corpus; a link into any other document keeps the English path on both sides, so a Chinese reader following it from a governed page lands on the English original and uses that page's switcher. And `pair-docs.py --check` resolves every relative link, so a path that drifted one directory too far is red rather than silently compared as text.
- The gate checks structure and recorded hashes, not meaning. Terminology and phrasing remain review's.
